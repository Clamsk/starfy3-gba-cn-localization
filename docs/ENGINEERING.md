# 不含原版素材的工程组织

[简体中文](ENGINEERING.md) | [English](ENGINEERING.en.md)

## 可复现基线

输入：用户自备、SHA256 符合 README 的原版镜像。

流程：原版校验 → BPS 校验与应用 → v25 输出校验 → 可选中文编辑 → 本地生成镜像。

没有中文编辑时输出与已验收的本地 v25 完全相同。公开工程用差异补丁保存已完成的代码、美术和字体修改，不包含研发过程中提取的完整官方图片、原文、英文参考 ROM 或历史测试 ROM。

## 中文文本和控制边界

中文表以 `脚本块:消息` 为键。每个记录列出 `slot` 和 `kind`，只有可编辑译文包含 `zh`。`control`、`end` 和 `preserved` 记录只表示边界，不含原始包或原文。

重建时从用户本地的 v25 基线恢复所有原始控制包。说话人包只替换姓名并更新长度；其他控制包逐字节保留。修改过的 BMG 重建 INF1 偏移与 DAT1 文本，放入预留空闲区域并更新所有对应指针。未修改的块不重建。

编辑器维持现有编码，只接受已经入库的字符和游戏按键图标。物品说明限制为每行 7 字、最多 5 行；普通对白、名称或其他界面仍必须结合实际窗口验收。调整色彩/换页边界需要单独工程处理，不能通过改动中文表的边界记录绕过检查。

## 字库和美术

`fonts/` 是开源字库源文件及许可证，不是原版游戏字库。BPS 中已经包含本版的字模修改。上游许可不因本项目的非商业政策改变。

所有未修改官方美术在应用补丁时从自备镜像读取。将来修改图块时，应在本地解码图块、调色板和映射，只公开必要差异或原创替换元素，避免提交完整官方素材与游戏截图。

## 重新生成补丁

本地修改并验收后，使用 Flips 差异模式生成新的 BPS：

```text
flips --create --bps-delta "local/original.gba" "local/Starfy3_CN_edited.gba" "local/candidate.bps"
```

检查补丁大小、动作统计、原版与目标 SHA256。用补丁还原并比较完整目标字节，检查 Git 跟踪清单后再更换发布文件。不要用包含大段搬移数据的线性补丁代替差异模式。

所有原版、目标、临时镜像、截图和存档留在 `local/` 或独立工作区。CI 不需要也不接收 ROM；CI 仅检查公开文件白名单及补丁格式。


## v25 标题署名的原创数据

`engineering/title_credit_v25.json` 仅包含原创署名“（v25）汉化 by Clamsk”的点阵索引和必要地址，不包含官方图像、调色板、原字库或截图。`scripts/add_title_credit.py` 可从自备的本地 v24 镜像重现 v25，只读提取需要保留的缓存，检查输入输出 SHA256，拒绝覆盖已有文件。该可选生成器使用 Python 标准库；当前 v25 的正常构建仍使用 README 的 BPS 流程。

```text
python scripts/add_title_credit.py --base "local/Starfy3_CN_v24.gba" --output "local/Starfy3_CN_v25_from_credit.gba"
```

署名使用现有 13 个标题精灵槽中的 5 个空白槽，原 START 提示保持原来的 6 个精灵；新字块使用原文字缓存中未使用的空白区。只修改 20 个标题动画帧，另外 38 帧和所有其他背景映射保持原样。为兼容 BIOS 的显存解压，新字块缓存使用无回溯的 LZ77 包，再由差异补丁引用原缓存的相同部分。
